# 同渠道通用视频脚本：COS URL 参考素材

完整复制 [xing-json-cos.js](./xing-json-cos.js) 到该渠道所需视频模型的「调用脚本」并保存。各模型用同一份脚本，`model` 原样读取当前选择，Base URL 和 API Key 也读取当前渠道。不要把模型名称写死或替换成文档别名。无需替换已成功的933脚本，也不改变其他渠道的默认协议。

## 上传与生成

- 本地图片、视频、音频 → 自己代理的 `/seedance/cos-upload` → 已配置的新加坡 COS（如 `https://sg-cos.maxai.art`）→ URL 数组提交给中转站。公网直链直接保留，包括原签名和素材顺序／重复项。私有签名URL须在排队和生成期间保持有效。
- 中转站仅收到 JSON，不收到 Base64、multipart、COS凭据或其他渠道素材库ID。本地代理的COS上传本身仍使用Base64，这是发给自己的后台，不是发给中转站。
- 不走 `/v1/videos/uploads`，不需要中转站 `file_id`，也不创建火山私域素材组。URL可访问不代表绕过平台的真人素材审核。
- 当前渠道完整COS配置优先，否则复用所有已有配置中唯一一套完整COS。多套不同配置时，填写脚本顶部 `COS_SOURCE_CHANNEL_ID`（渠道内部ID，不是名称或网址），或给当前渠道绑定所需COS；不猜选来源。公网URL／纯文字生成不需要COS。
- 图片均按参考图提交，不支持通过本脚本实现首尾帧或草稿；不要期待面板的帧模式改变本脚本语义。提示词原样保留，不自动改写@图片标记；图片数组顺序保留。

## 协议范围

沿用之前提供的933协议：`POST /v1/videos/generations`，JSON字段 `model / prompt / duration / resolution / ratio / n:1 / images / videos / audios / generate_audio`；后续 `GET /v1/videos/{id}`。本脚本通用的是模型名称和COS上传，不代表兼容任意视频API。新增两个模型仍需支持上述路径、字段及完成响应；若不同，请提供对应文档后仅调整脚本。

时长、分辨率和音轨按节点参数提交，不强加933的4–15秒／720p等模型专属限制，也不宣称新模型支持全部档位。当前画布传给脚本的参数仍受已有节点UI／规范化逻辑影响；本脚本不会新增模型控件。未填写比例或auto时使用16:9，未填写分辨率时使用720p。

## 后台与安装

沿用现有 `json-video` 后台：只提交一次生成POST，后台每10秒查询原任务，按已有规则持久化完成视频24小时。刷新／查询原任务不重跑脚本或重新生成。COS上传准备阶段仍在网页执行，最终生成POST受理后才交由后台持续等待。服务停止会中断尚未完成的请求，不会自动补发。

该脚本自带COS配置查找，不依赖新加入的 `uploadToCos` 注入变量；已部署版本若具备 `/seedance/cos-upload`、`json-video`后台协议与单步自定义视频领取功能，只需保存脚本，无需为本次改动更新镜像或重启服务。旧任务不会因换脚本自动重提。

本次未调用真实平台／COS、未执行构建或测试、未修改浏览器设置、未提交Git或发布镜像。请先在两个新增模型各以少量素材手动验收；平台权限、模型规格及生成效果尚未实测。
